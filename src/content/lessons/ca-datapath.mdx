## How to Design a Processor - Step by Step
## Step 1：分析 instruction set
=> data path requirements
- instruction set define 了這個 processor 能做到什麼事情
- the meaning of each instruction is given by the register transfers
- datapath must include storage element for ISA registers
- datapath must support each register transfer
- the RISC-V subset for today：
  `add rd, rs1, rs2`
  `sub rd, rs1, rs2`
  `ori rd, rs, imm12`
  `ld rd, imm12(rs1)`
  `beq rs1, rs2, imm12`
  ![RISC-V subset](https://hackmd.io/_uploads/HJQ9EXlsMg.png)
- execution flow（影片大約五分鐘的地方有動畫）：Instruction Fetch -> Instruction Decode -> Operand Fetch -> Execute -> Result Store
- instruction &lt;=> register transfers
    - RTL（Register Transfer Languages）gives the meaning of the instructions
    - all start by fetching the instruction
    - ![fetching the instruction](https://hackmd.io/_uploads/SJUw_meszx.png)
- requirements of the instruction set
    - memory（instruction & data）
    - registers（read `RS1`、read `RS2`、write `RD`）
    - PC
    - extender
    - add and sub register or extended immediate
    - add 4 or extended immediate to PC
## Step 2：挑 datapath 要用的 components、建立 clocking methodology
- clocking methodology：combinational logic transforms data during clock cycles
   - ![clocking methodology](https://hackmd.io/_uploads/S1ouaCgiMe.png)
   - between clock edges
   - input from state elements, output to state element
   - longest delay determines clock period
- combinational elements
   - the outputs only depend on the current inputs
   - example：ALU
   - ![combinational elements](https://hackmd.io/_uploads/H1YTgRljzx.png)
- storage elements（state element）
   - the outputs depend on both their inputs and the contents of the internal state
   - at least two inputs and one output
       - inputs - input data and clock（clocking methodology）
       - output - the value stored on a state element
   - example：D Flip-Flop, register and memory
   - storage element - register（basic building block）：stores data in a circuit
       - uses a clock signal to determine when to update the stored value（edge-triggered：update when `Clk` changes from 0 to 1）
       - write enable：asserted -> update the register contents
       - ![register](https://hackmd.io/_uploads/rJAwPCgsGx.png)
   - storage element - register file
       - ![register file](https://hackmd.io/_uploads/S1wIoAloGx.png)
       - register file consists of 32 registers：
           - 2 64-bit output busses：busA and busB
           - 1 64-bit input but：busW
       - register is selected by：
           - RA（number）selects the register to put on busA（data）
           - RB（number）selects the register to put on busB（data）
           - RW（number）selects the register to be written via busW（data）when Write Enable is 1
       - clock input（CLK）
           - the CLK input is a factor ONLY during write operation
           - during read operation, behaves as a combinational logic block：RA or RB valid => busA or busB valid after "access time"
   - storage element - memory
       - ![memory](https://hackmd.io/_uploads/ryAEhCxszl.png)
       - memory
           - 1 input bus：data in
           - 1 output but：data out
       - memory word is select by：
           - address selects the word to put on Data Out
           - Write Enable = 1：address selects the memory word to be written via the Data In bus
       - clock input（CLK）
           - the CLK input is a factor ONLY during write operation
           - during read operation, behaves as a combinational logic block：address valid => Data Out valid after "access time"
## Step 3：assemble datapath meeting the requirements
- register transfer requirements -> datapath assembly
 ![datapath assembly](https://hackmd.io/_uploads/BJLUgy-ifg.png)
 步驟：
   1. instructions fetch
   2. read operands and execute operation
   3. memory read / write
   4. register update
- 3a. instruction fetch unit：common operations
 ![instruction fetch unit](https://hackmd.io/_uploads/rJfvZ1WiMl.png)
   - fetch the instruction：`mem[PC]`
   - update the program counter：
     sequential code `PC <- PC + 4`
     branch and jump（later） `PC <- target addr.`
- 3b. add & subtract
  ![add & subtract](https://hackmd.io/_uploads/S1GdX1bizg.png)
    - `R[rd] <- R[rs1] op R[rs2]`，example：`add rd, rs1, rs2`
        - Ra, Rb and Rw come from instruction's rs1, rs2 and rd files
        - ALUctr and RegWr：control logic after decoding the instruction
- 3c. load operations
  ![load operations](https://hackmd.io/_uploads/SJ7MEkWjMg.png)
    - `R[rd] <= mem[R[rs1] + SignExt[imm12]] # ld rd, imm12(rs1)`
- 3e. branch operations
  ![branch operations - instruction](https://hackmd.io/_uploads/rkrrwy-sfl.png)
  ![branch operations](https://hackmd.io/_uploads/HytUwJZozg.png)
    - `beq rs1, rs2, imm12`
    - ```c
      if( rs = rt )
          PC <- PC + ( SignExt( imm12 ) * 2 )
      else
          PC <- PC + 4
      ```
- single-cycle datapath：attempt to execute all instructions in one clock-cycle

  - add instruction 的 data flow

## Performance of Single-Cycle Machines
assumption
- memory units：200ps
- ALU and adders：100ps
- register file（read or write）：50ps
- instruction mix：
    - 25% loads, 10% stores, 45% ALU instructions, 15% branches, and 5% jumps
- comparison
    - every instructions operates in 1 clock cycle of a fixed length
    - every instruction executes in 1 clock cycle using a variable-length clock

![units used](https://hackmd.io/_uploads/HJCKA-Wjze.png)

recall：CPU execution time = instruction count * CPI * clock cycle time，since CPI must be 1, can simplify to：CPU execution time = instruction count * clock cycle time

for fixed clock cycle implementation
- the clock cycle for each instruction is determined by the longest instruction, load, which is 600ps（200 + 50 + 100 + 200 + 50）

for variable clock cycle implementation
- the average time per instruction with a variable clock is：600 * 25% + 550 * 10% + 400 * 45% + 350 * 15% + 200 * 5% = 447.5ps

the variable clock implementation would be faster by $\frac{600}{447.5}=1.34$
