## Instruction Set Architecture
instruction set architecture 是軟體跟硬體之間的 interface
![instruction set architecture 1](https://hackmd.io/_uploads/ryj1cng9zg.png)
![instruction set architecture 2](https://hackmd.io/_uploads/BJxZq3g5Ge.png)
ISA design principle：To find a language that makes it easy to build the hardware and the compiler while maximizing performance and minimizing cost.（hardware 簡單，這樣才會速度快，才會省點）
> "It is easy to see by formal-logical methods that there exist certain [instruction set] that are in abstract adequate to control and cause the execution of any sequence of operations....The really decisive considerations from the present point of view, in selecting an [instruction set], are more of a practical nature: simplicity of the equipment demanded by the [instruction set], and the clarity of its application to the actually important problems together with the speed of its handling of those problems."
> 「透過形式邏輯方法很容易看出，存在某些［指令集］，它們在抽象層面上足以控制並促成任何操作序列的執行……。從當前的觀點來看，在選擇［指令集］時真正具決定性的考量更多是基於實用性質：即該［指令集］所需的設備簡潔度、其應用於實際重要問題時的清晰度，以及其處理這些問題的速度。」
> \- Burks, Goldstine, and von Neumann, 1947

a good interface：
- lasts through many implementations（portability, compatibility）
- is used in many different ways（generality）
- provides convenient functionality to higher levels
- permits an efficient implementation at lower levels

各種不同的 use 傳到 interface，後面的 implement 由 imp1 -> imp2 -> imp3 按照順序實作：

instruction 的運作：
![how does instructions function](https://hackmd.io/_uploads/r1bHjnxqGe.png)
general purpose register ISA：
- register-memory
  ```asm
  add R1 A ; R1 = R1 + mem[A]
  add R2 R1 A ; R2 = R1 + mem[A]
  ```
- register to register（load-store）
  ```asm
  add R2 R1 R3 ; R2 = R1 + R3
  load R3 A ; R3 = mem[A]
  store R3 A ; mem[A] = R3
  ```
有兩種：
以 perform `A * B` 為例，假設 A 放在 2:3、B 放在 5:2（`A->2:3`、`B->5:2`）
1. RISC（reduced instruction set architecture）
   ```asm
   load A, 2:3
   load B, 5:2
   multi A, B
   store 2:3, A
   ```
   example：ARM、MIPS、RISC-V
2. CISC（complex instruction set architecture）
   ```asm
   mult 2:3, 5:2
   ```
   example：intel x86

## Arithmetic Operations & Registers
arithmetic operations（加減乘除）
- design principle 1 - simply favors regularity，所以 1 個 operation 要有剛好 3 個 operand
  ```asm
  add a, b, c
  ```
  a 是 destination、b 跟 c 是 source
  example：`f=(g+h)-(i+j);`
  ```asm
  add t0, g, h
  add t1, i, j
  sub f, t0, t1
  ```
- design principle 2 - smaller is faster（所以不會到 256-bit 那麼大）
  operand 要 store 在 register（registers are primitive used in hardware design that are also visible to programmers）
  RISC-V has a 32 x 64-bit register file
  - use for frequently accessed data
  - 64-bit data is called a "doubleword"
      - 32 x 64-bit general purpose registers x0 to x31
  - 32-bit data is called a "word"

RISC-V registers（不用細看）

| register | 功用 |
| - | - |
| x0 | the constant value 0 |
| x1 | return address |
| x2 | stack pointer |
| x3 | global pointer |
| x4 | thread pointer |
| x5-x7 x28-x31 | temporaries |
| x8 | frame pointer |
| x9 x18-x27 | saved registers |
| x10 x11 | unction arguments/results |
| x12-x17 | unction arguments |

example：
- C code：`f=(g+h)-(i+j)`（f g h i j 在 x19-x23）
- compiled RISC-V code
  ```asm
  add x5, x20, x21
  add x6, x22, x23
  sub x19, x5, x6
  ```
## Memory Operations：Load and Store
load operands from & store results to memory：data transfer instructions
- ```asm
  lw x9, 8(x22) ; x9 = mem[8+reg[x22]]
  ```
- ```asm
  sw x9, 8(x22) ; mem[8+reg[x22]] = x9
  ```

example：
- C code：`A[12] = h + A[8]`（h 在 x21、A 的 base address 在 x22）
- compiled RISC-V code
  ```asm
  ld x9, 64(x22) ; x9 = mem[x22 + 64 / 8] = mem[x22 + 8] = A[8]
  add x9, x21, x9
  sd x9, 96(x22) ; mem[x22 + 96 / 8] = mem[x22 + 12] = A[12] = x9
  ```
  offset 是什麼？每個 element 是兩個 word，所以要放 index * 8，所以在這個 example 要放 12 * 8

## Conditional Operations
branch to a labeled instruction if a condition is true（otherwise continue sequentially）
- assembly：
  ```asm
  beq rs1, rs2, L1
  ```
  C：
  ```c
  if( rs1 == rs2 )
      branch to instruction labeled L1
  ```
- assembly：
  ```asm
  bne rs1, rs2, L1
  ```
  C：
  ```c
  if( rs1 != rs2 )
      branch to instruction labeled L1
  ```
- assembly：
  ```asm
  blt rs1, rs2, L1 ; branch if less than
  ```
  C：
  ```c
  if( rs1 < rs2 )
      branch to instruction labeled L1
  ```
- assembly：
  ```asm
  bge rs1, rs2, L1 ; branch if greater or equal
  ```
  C：
  ```c
  if( rs1 >= rs2 )
      branch to instruction labeled L1
  ```
  example - 用 assembly 寫出 `if( a > b ) a += 1;`、a in x22、b in x23
  ```asm
   bge x23, x22, Exit
   addi x22, x22, 1
  Exit:
  ```
- assembly：
  ```asm
  slt reg1, reg2, reg3 ; set less than
  ```
  C：
  ```c
  if( reg2 < reg3 )
      reg1 = 1; // set
  else reg1 = 0; // reset
  ```

| - | - | - |
|  | `blt`, `bge` | `bltu`, `bgeu` |

## Basic Block
basic block 是一連串的 instructions，滿足：
- 只有最後一個 instruction 是 branch（no imbedded branches expect at the end）
- 只有第一個 instruction 是 branch 的 target（no branch targets except at the beginning）

=> 一個 basic block 裡面的 instruction 一定會一起執行
- a compiler identifies basic blocks for optimization
- an advanced processor can accelerate execution of basic blocks

## Procedure
procedure 在 high level language 裡面很簡單，現在有兩個 procedure 以 high level language 的形式的 code，`f1()` 跟 `f2()`，`f2()` 裡面會 call `f1()`，所以 `f2()` 是 caller、`f1()` 是 callee
```c
int f1( int i, int j, int k, int g ){
    // ...
    add x9, x7, x8;
    return 1;
}

int f2( int s1, int s2 ){
    // ...
    add x9, x10, x11;
    i = f1( 3, 4, 5, 6 );
    add x7, x8, x9; // <- PC
    // ...
}
```
要把 high level language 轉乘 assembly 有這些 steps required：
1. place parameters in registers x10 to x17
2. transfer control to procedure
3. acquire storage for procedure
4. perform procedure's operations
5. place result in register for caller x10 / x11
6. return to place of call（address in x1）

procedure call instructions
- procedure call：jump and link
  `ja1 x1, ProcedureLabel`
  - 會把 PC 設成 `ProcedureLabel` 的位址（jumps to target address）
  - 然後把原本的位址存在 `x1`（address of following instruction put in `x1`）
  - 圖
    ![截圖 2026-09-25 20.56.03](https://hackmd.io/_uploads/HkVOkl4qfg.png)
- procedure return：jump and link register
  `jalr x0, 0(x1)`
  - like `jal`, but jumps to `0 + address in x1`（`PC = 0 + address in x1`）
  - use `x0` as `rd`（`x0 cannot be changes`）
  - can also be used for computed jumps（ex. for `case` / `switch` statements）

leaf procedure example：
- C code（`ll` 是 `long long int`）：
  ```c
  ll leaf_example( ll g, ll h, ll i, ll j ){
      ll f;
      f = ( g + h ) - ( i + j );
      return f;
  }
  ```
  - arguments g ... j in x10 ... x13
  - f in x20
  - temporaries x5, x6
  - need to save x5, x6, x20 on stack
- RISC-V code：
  ```asm
  // allocate space for procedure，下圖的 (a) -> (b)
  addi sp, sp, -24
  sd x5, 16(sp)
  sd x6, 8(sp)
  sd x20, 0(sp)
  
  // 做 f = ( g + h ) - ( i + j );
  add x5, x10, x11
  add x6, x12, x13
  sub x20, x5, x6
  
  // 做 return f;
  addi x10, x20, 0
  
  // restore space，下圖的 (b) -> (c)
  ld x20, 0(sp)
  ld x6, 8(sp)
  ld x5, 16(sp)
  addi sp, sp, 24
  
  // 最後 rerturn
  jalr x0, 0(x1)
  ```
  ![截圖 2026-09-25 21.10.40](https://hackmd.io/_uploads/r11kQeVcGe.png)
  - x5 – x7, x28 – x31：temporary registers（not preserved by the callee）
  - x8 – x9, x18 – x27：saved registers（if used, the callee saves and restores them）
- 再簡化後的 RISC-V code：
  ```asm
  addi sp, sp, -24
  ; sd x5, 16(sp)
  ; sd x6, 8(sp)
  sd x20, 0(sp)
  add x5, x10, x11
  add x6, x12, x1
  sub x20, x5, x6
  addi x10, x20, 0
  ld x20, 0(sp)
  ; ld x6, 8(sp)
  ; ld x5, 16(sp)
  addi sp, sp, 24
  jalr x0, 0(x1)
  ```
  save `x5, x6, x20` on stack
  ```c
  x5 = g + h
  x6 = i + j
  f = x5 - x6
  ```
  copy `f` to return register
  restore `x5, x6, x20` from stack

non-leaf procedure example（算 `1 * 2 * 3 * ... * n`）：
- C code：
  ```c
  ll fact( ll n ){
      if( n < 1 ) return 1;
      else return n * fact( n - 1 );
  }
  ```
  - argument n in `x10`
  - result in `x10`
- RISC-V code：
    ```asm
    fact:
        addi sp, sp, -16 ; save return address x1 and n x10 on stack
        sd x1, 8(sp)
        sd x10, 0(sp)
        addi x5, x10, -1 ; x5 = n - 1
        bge x5, x0, L1 ; if n >= 1, go to L1
        addi x10, x0, 1 ; else, set return value to 1
        addi sp, sp, 16 ; pop stack, don't bother restoring values
        jalr x0, 0(x1) ; return
    L1: addi x10, x10, -1 ; n = n - 1
        jal x1, fact ; call fact(n - 1)
        addi x6, x10, 0 ; move result of fact( n - 1 ) to x6
        ld x10, 0(sp) ; restore caller's n
        ld x1, 8(sp) ; restore caller's return address
        addi sp, sp, 16 ; pop stack
        mul x10, x10, x6 ; return n * fact( n - 1 )
        jalr x0, 0(x1) ; return
    ```

## Byte / Halfword / Word Operations
RISC-V byte / halfword / word 的 load / store：
- load byte / halfword / word：sign extend to 64 bits in `rd`（sign extended：最高位是 1 就把前面沒滿的補 1、是 0 就補 0）
    - `lb rd, offset(rs1)`
    - `lh rd, offset(rs1)`
    - `lw rd, offset(rs1)`
- load byte / halfword / word unsigned：zero extend to 64 bits in `rd`
    - `lbu rd, offset(rs1)`
    - `lhu rd, offset(rs1)`
    - `lwu rd, offset(rs1)`
- store byte / halfword / word：store rightmost 8 / 16 / 32 bits
    - `sb rs2, offset(rs1)`
    - `sh rs2, offset(rs1)`
    - `sw rs2, offset(rs1)`

string copy example：
- C code（null-terminated string）
  ```c
  void strcpy( char x[], char y[] ){
      size_t i;
      i = 0;
      while( ( x[i] = y[i] ) != '\0' )
          i += 1;
  }
  ```
- RISC-V code（x 在 x11、y 在 x10）：
  ```asm
  strcpy:
      addi sp, sp, -8 ; adjust stack for 1 doubleword
      sd x19, 0(sp) ; push x19
      add x19, x0, x0 ; i = 0
  L1: add x5, x19, x11 ; x5 = addr of y[i]
      lbu x6, 0(x5) ; x6 = y[i]
      add x7, x19, x10 ; x7 = addr of x[i]
      sb x6, 0(x7) ; x[i] = y[i]
      beq x6, x0, L2 ; if y[i] == 0 then exit
      addi x19, x19, 1 ; i = i + 1
      jal x0, L1 ; unconditional jump, next iteration of loop
  L2: ld x19, 0(sp) ; restore saved x19
      addi sp, sp, 8 ; pop 1 doubleword from stack
      jalr x0, 0(x1) ; and return
  ```

## Parallelism and Instructions：Synchronization
parallel tasks must synchronize to avoid data race, where the results of the program can change depending on how events happen to occur.
lock / unlock: ensure only one task entering the critical section：
- P(1)
  ```c
  acquire lock;
  if lock = 0
      enter critical section;
  release lock;
  ```
- P(2)
  ```c
  acquire lock;
  if lock = 0
      enter critical section;
  release lock;
  ```

atomic swap：atomically intercharge a value in a register for a value in memory; nothing else can interpose itself between the read and write to the memory location
- P(1)
  ```c
  x4 = 1;
  swap(x4, lock);
  if x4 = 0
      enter critical section;
  ```
  ![截圖 2026-09-29 15.02.03](https://hackmd.io/_uploads/Hk_OzkKcze.png)
  ```asm
          li x4, #1
  lockit: lw x2, 0(x1)
          sw x4, 0(x1)
          bnez x2, lockit
  ```
- P(2)
  ```c
  x4 = 1;
  swap(x4, lock);
  if x4 = 0
      enter critical section;
  ```
  ![截圖 2026-09-29 15.02.57](https://hackmd.io/_uploads/HJRof1KcGl.png)
  ```asm
          li x4, #1
  lockit: lw x2, 0(x1)
          sw x4, o(x1)
          benz x2, lockit
  ```

initial value of lock is 0
`lw x2, 0(x1) // processor 1`
`lw x2, 0(x1) // processor 2`
`sw x4, 0(x1) // processor 1`
`sw x4, 0(x1) // processor 2`
=> both processors think they get the lock

synchronization in RISC-V：
- loak reserved：`lr.d rd, (rs1)`
    - load from address in `rs1` to `rd`
    - place reservationon memory address
- store conditional：`sc.d rd, (rs1), rs2`
    - store from `rs2` to address in `rs1`
    - succeed if location not changed since the `lr.d`（returns 0 in `rd`）
    - fails of location is changed（returns non-zero value in `rd`）

- example：atomic swap（to test or set lock variable, lock variable is stored at `[x20]`, `x23` initially set to 1）
  ```asm
  again: lr.d x10, (x20)
         sc.d x11, (x20), x23 ; x11 = status
         bne x11, x0, again ; branch if store failed
         addi x23, x10, 0 ; x23 = loaded value
  ```
- example：lock
  ```asm
         addi x12, x0, 1 ; copy locked value
  again: lr.d x10, (x20) ; read lock
         bne x10, x0, again ; check if is 0 yet
         sc.d x11, (x20), x12 ; attempt to store
         bne x11, x0, again ; branch if fails
         unlock:
         sd x0, 0(x20) ; free lock
  ```

助教答案：
```asm
sum:
	addi sp, sp, -16
	sd ra, 8(sp)
	beq a0, x0, base_case
	add a1, a1, a0 # acc = acc + n
	addi a0, a0, -1 # n = n - 1
	jal ra, sum
	ld ra, 8(sp)
	addi sp, sp, 16

base_case:
	addi a0, a1, 0 # return acc
	ld ra, 8(sp)

```
**2.**
判斷一個程式是否為 tail call：遞迴回來之後，沒有任何指令使用或修改回傳值，只剩復原 stack frame 和返回 => 這題是 tail call
為什麼可以做 tail call optimization（TCO）：普通遞迴會一層一層呼叫，再一層一層返回，但 tail call 在返回的時候，每一層只是把同樣的回傳值往上傳，所以可以讓最後一層直接返回給第一層，省掉整段回程
TCO 的效果：遞迴變成迴圈，計算順序不變，stack 空間從 O(n) 變成 O(1)
把這題做 TCO：
```asm
sum:
    beq a0, x0, base
    add a1, a0, a1
    addi a0, a0, -1
    jal x0, sum
base:
    mv a0, a1
    jalr x0, 0(ra)
```
