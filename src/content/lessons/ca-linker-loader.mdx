## Starting a Program
![starting a program](https://hackmd.io/_uploads/SksmoKyizg.png)
- Assembler：
    - 把 assembly language 轉成 object file
    - object file 裡面的 symbol table：a table that matches names of labels to the address of the memory words that instruction occupy
    - object file：
      ![object file](https://hackmd.io/_uploads/rkTyTF1sfl.png)
    - 把 psudoinstruction 轉成真正的 instruction set 有 support 的 real instructions
      `li x9, 123` -> `addi x9, x0, 123`
      `mv x10, x11` -> `addi x10, x11, 0`
- linker（link editor）：
    - linker takes all the independently assembled machine language programs and "switches" them togethor to produce an executable file that can be run on a computer
    - linker 有三個步驟：
      1. place code and data modules symbolically in memory
      2. determine the address of data and instruction labels
      3. patch both the internal and external references
    - example（有兩個 object file）
      ![linker example](https://hackmd.io/_uploads/S1HWI51jGx.png)
## Loading a Program
```asm
main();

_start_up:
lw x10, offset($sp) ## load arguments
jal x1, main;
exit
```
1. read header to determine segment sizes
2. create virtual address space
3. copy text and initialized data into memory（or set page table entries so they can be faulted in）
4. set up arguments on stack
5. initialize registers（including `sp`、`fp`、`gp`）
6. jump to startup routine
    - copies arguments to `x10`, ... and calls main
    - when main returns, do exit syscall

## Dynamically Linked Libraries (DLL)
statically linked library 的壞處：
- library updates
- loading the whole library even if all of the library is not used

dynamic linked library：
- library not linked and loaded until the program is run
- lazy procedure linkage（each routine is linked only after it is called）
- dynamic linker：不會一次把要 link、要 call 的 library 拿進來

## MIPS instructions
- MIPS：commercial predecessor to RISC-V
- similiar basic set of instructions
    - 32-bit instructions
    - 32 general purpose registers, register 0 is always 0
    - 32 floating-point registers
    - memory accessed only by load / store instructions
        - consistent use of addressing modes for all data sizes
- different conditional branches
    - for `<`, `<=`, `>`, `>=`
    - RISC-V：`blt`、`bge`、`bltu`、`bgeu`
    - MIPS：`slt`、`sltu`（set less than, result is 0 or 1）
        - then use `beq`, `bne` to complete the branch

RISC-V 有五種、MIPS 只有三種
![instruction encoding](https://hackmd.io/_uploads/rka9r1xjfx.png)

RISC-V 跟 MIPS 其實很接近，Intel x86 就很不一樣

x86 registers：
![x86 registers9](https://hackmd.io/_uploads/BJNVfbxjfl.png)
2 operands per instruction

| source / dest operand | second source operand |
| - | - |
| register | register |
| register | immediate |
| register | memory |
| memory | register |
| memory | immediate |

memory addressing modes：
- address in register
- address = R_base + displacement
- address = R_base + 2^scale * R_index + displacement
- address = R_base + 2^scale * R_index + displacement（ex. `MOV EAX, [EDX + EBX*4 + 8]`）

x86 instruction encoding
![x86 instruction encoding](https://hackmd.io/_uploads/H1KQEWeize.png)

implementing IA-32
- complex instruction set makes implementation difficult
    - hardware translates instructions to simpler microoperations
        - simple instructions：1 - 1
        - complex instructions：1 - many
    - microengine similar to RISC
    - market share makes this economically viable
- comparable performance to RISC
    - compilers avoid complex instructions

## Fallacies
- powerful instruction => higher performance
    - fewer instructions required
    - but complex instructions are hard to implement（may slow down all instructions, including simple ones）
    - compilers are good at making fast code from simple instructions
- use assembly code for high performance
    - but modern compilers are better at dealing w/ modern processors
    - more lines of code => more errors and less productivity
- Backward compatibility => instruction set
doesn't change
    - but they do accrete more instructions
      ![x86 instruction set](https://hackmd.io/_uploads/H1u5TGxiGe.png)

### 10/7 分組討論題
#### Q1
![1007 class q1.1](https://hackmd.io/_uploads/HJJlzCj2Mg.png)
![1007 class q1.2](https://hackmd.io/_uploads/H1cef0j3Gx.png)
(a)
合起來
```c
int x;
int main () {}
int x;
int main () {}
```
會失敗，因為有兩個 main function，都是 strong symbol，違反 rule 1
(b)
合起來
```c
void f();
int x = 3;
int y = 5;
int main () {
	f();
	printf("0x%x 0x%x\n", x, y)
};
double x;
void f () { x = -0.0; }
```
linker 會選 `int x = 3`，因為他是 strong symbol，所以 x 是 int，佔 4 bytes
執行 `f()` 的時候：`x = -0.0`（-0.0 = 0x8000000000000000）會誤產生一條寫入 0x0000000000000080（little-endian 這樣存）的指令（double 有 8 byte），但其實前面 4 byte 是 x 的、後面 4 byte 是 y 的
所以現在 x 存了 0x00000000、y 存了 0x00000080，然後 printf 會把順序倒回來，所以 x 會輸出 0x0、y 會輸出 0x80000000
=> `0x0 0x80000000`
